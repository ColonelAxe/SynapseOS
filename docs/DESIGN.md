# SICS visual specification

## v0.4 chat and explicit map tools

Messages uses a native scrollable conversation group instead of an operations list. Message cards distinguish own/sent updates by colour and alignment, show the sender and mission-elapsed timestamp, preserve paragraph breaks, and escape user text before structured rendering. The bottom composer sends on Enter, inserts a new line on Shift+Enter, and clears a draft only after server acceptance if that draft has not already changed. Broadcast and element conversations reuse the existing authorised message service.

The main map border contains three persistent, labelled tools. Markers opens its menu immediately and can arm a symbol for click placement. Line drawing uses an explicit two-click start/end workflow with a live preview and right-click cancellation/deletion. Grid selector simply attaches a location to a transmission. The current mode is highlighted and explained in the footer. Messages retains a compact context map; its main chat area is reserved for conversation.

Line objects share the same bounded, side-filtered server store and owner/commander permissions as icon markers, and render as native Arma polylines. No new radio propagation or attachment service is implied.

## v0.2.1 simple tablet and map markers

Native rendering now uses a purpose-built rounded graphite frame texture with a small camera and an inset dark screen. Its viewport is centred, capped to 95% of the available display, and kept at a 16:10 physical aspect ratio. All native control coordinates are transformed through the same viewport. This avoids a stretched full-screen rectangle on a 4:3 game window or an ultrawide display. Section bars use dark navy and blue text; bright blue is reserved for the active application and primary actions.

Map double click opens a native-marker editor. It uses the loaded Arma `CfgMarkers` symbols and standard marker colours, with a label, rotation and size. Grid selection remains available through Grid only. Browser preview markers are local simulations; the addon validates and relays native local markers to the authorised side. The rounded frame asset is generated by `tools/create-tablet-frame.ps1` and converted to PAA with installed Arma Tools.

## v0.2 reference-led tablet redesign

The supplied `c2.png`, `messages.png` and `tabletui1.png` guide composition, contrast and device framing. Their annotation boxes, background scenery and ATLAS branding are not part of the interface. SICS keeps its own name and does not embed the supplied screenshots as a flat UI image.

- Tactical: large map, compact force roster and an operations / ISR rail.
- C2: organization column, operational map, selected-element identity and Overview / Composition / Capabilities / Status tabs, with a separate bottom command strip. The native Arma details use Overview / Team / Role / Status and read live group identity, personnel, position and movement.
- Messages: channel directory, conversation column with bottom composer, and a channel context panel. The native layout uses a transmission list and selected-message body with a map in the context column.
- Device: layered graphite chassis, inset dark screen, blue section bars, cyan-blue active tabs, red close control and NATO-friendly blue symbols. HTML uses CSS geometry; Arma uses native background/control layers.

Open `preview/index.html` and choose C2 or Messages to inspect the redesign. `sics-c2-redesign.png` and `sics-messages-redesign.png` are actual browser renders. The preview's channel membership, unit readiness, terrain and conversations are simulated. Native controls use SynapseOS-owned data and transmission functions; this redesign does not add AI command automation, attachment transport or an RF model.

v0.2 was statically built and browser tested. The live screenshot from v0.1 documents the previous layout; v0.2 still requires an in-game layout pass.

The implemented interface reference is `sics-interface.png`. Open `preview/index.html` for the interactive version. Image generation was attempted twice but the provider rejected both outputs; the reference is an actual screenshot of the implemented browser interface.

The visual workflow was informed by established Arma tablet conventions, but the current device model, map data and runtime are SynapseOS-owned and use vanilla Arma assets. The main view has a compact header, six persistent workspaces, a friendly force roster, a dominant tactical map and an operations / ISR rail. The map stays visible while composing messages, orders and reports. Double clicking selects the attached grid. NATO icons and muted colours distinguish the shared picture from interface controls.

The Arma display uses safe-zone coordinates and engine-native RobotoCondensed, list controls and map controls. It shares this composition and palette. It is not pixel-identical to the browser rendering: terrain comes from the loaded Arma world, symbology uses the SynapseOS/Arma marker catalogue, the roster is a native list, and ISR is an engine camera target. The browser's map, unit positions, connection state and sensor feed are explicitly simulated.

## Workspaces

- Overview: maximum map area, force roster and operations feed.
- Messages: recipient group, priority and shared transmissions.
- ISR: friendly UAV selection, embedded driver camera and native UAV terminal handoff.
- C2: group-targeted or side-wide orders, geospatial attachment and recipient acknowledgements.
- Reports: field reports with selected map grid.
- TOC: mission-defined command terminal access. A TOC is a collection of authorised terminals placed in a room, not a newly modelled building.
